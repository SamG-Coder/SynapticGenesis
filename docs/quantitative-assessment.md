# Native quantitative baseline handoff

This stage prepares read-only assessment of the completed 105M and 411M
prose checkpoints on [quantitative-development-v2](quantitative-probes.md).
It creates no new learner. The checkpoints have both completed the same
216,289 source observations and 27,680,129 next-byte targets from the
selected prose curriculum, with matched replay and scheduled-speech exposure.
The [completed size comparison](prose-411m-results.md) supplies their origin
and previous text-prediction results.

The [fixed specification](../data/quantitative-assessment-v1.json) names the
exact checkpoint hashes, prepared question suite, published source evidence,
candidate runtime and predecessor study. The runtime is the already accepted

has consumed the prepared arithmetic/Physics continuation.

## Work and serial execution

Each model receives one `language-probes` command covering all 128 items and
eight longer `sample` commands: 18 native commands in total. The samples
always use the first numerical group, unswapped context and trial A from
each skill. This choice is fixed before seeing responses. Each continuation
has 128 bytes, seed 42, temperature 0.8 and top-k 40.

The launcher declares its inputs and holds a Windows process handle for
the complete membrane-study Python driver. Its PID, executable and creation
time must match. It waits for a normal exit and consistent completion records
for all 15 models before launching any native assessment. That completion
check establishes serial GPU use; it does not re-audit all numerical evidence
from the predecessor experiment. Failed exit, a reused process identity or
incomplete predecessor evidence starts no assessment command.

Only immutable stage-four checkpoints are used. Full file hashes are checked
before and after scoring, and the native probe command independently checks
its weight and optimizer arrays for mutation. Every command, log, per-item
likelihood, generated answer, long sample and resulting file hash is retained.
The current source edition must remain admitted; renaming a checkpoint or
source does not change the provenance checks.

## Result interpretation

Report item accuracy, all-four-in-group accuracy, exact greedy answers,
per-skill results and the declared heuristic controls separately. The suite
contains only four numerical groups per skill, has fixed wording and is a
development diagnostic. It is not a broad generalization or reproduction gate.

The probe scorer uses strict FP32 and independent zero-state candidates.
Long illustrative samples use graph sampling under the complete checkpoint's
saved math policy. These are different measurement settings. A short exact
answer failure can involve output formatting as well as numerical ability;
the longer raw samples allow that distinction to be inspected.

Native probe JSON maps each generated byte to a U+00xx character. The reader
recovers those original bytes with Latin-1 and retains their hex encoding;
UTF-8 replacement characters are only a display view. The native report
prints likelihoods with 12 significant digits. When those printed values
cannot distinguish a decision from the native 1e-8 tie boundary, the audit
retains the reported decision and counts the ambiguity. Contradictory
decisions are rejected. All reported counts, skill scores and loss aggregates
are recomputed with bounds for that serialization precision.

Assessment elapsed time includes repeated context/candidate forwards and
GPU/CPU transfers. It is not isolated generation throughput. No result here
would justify comparing this duration directly with live training byte rates.

## Verification status

The [host audit](../reports/quantitative-assessment-host-checks.json) passes
30 rejection cases, including altered scores, labels, groups, output bytes,
aggregates, predecessor results and process identities. It checks 18 mocked
commands across two synthetic model records and authenticates 409 real input
files, including the two complete checkpoints. Those mock scores are control
tests only. **The host audit runs zero native commands and establishes no
model-quality result.**

`quantitative_assessment_inputs.py` owns source/checkpoint admission and
fixed command construction; `quantitative_assessment.py` owns declaration,
process serialization and native orchestration; `quantitative_report.py`
owns interpretation of the saved native output. All model computation remains
in the existing native executable and shared forward implementation.

From the main workspace, the preparation commands use this branch's scripts:

```powershell
python -X utf8 runs/quantitative-probes-worktree/tests/quantitative_assessment.py --report <fresh-host-report.json>
python -X utf8 runs/quantitative-probes-worktree/scripts/quantitative_assessment.py declare --workspace D:/SynapticGenesis --out <fresh-run-directory> --wait-pid <live-study-driver-pid> --wait-executable <actual-python-executable>
python -X utf8 runs/quantitative-probes-worktree/scripts/quantitative_assessment.py run --out <declared-run-directory> --protocol-sha256 <declared-protocol-hash>
```

Declaration and a waiting process do not establish successful model scoring.
The native results remain pending until the predecessor and all 18 commands
complete and their output checks pass.
