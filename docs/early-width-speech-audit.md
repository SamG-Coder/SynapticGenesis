# Early-width speech audit correction

The first early-width attempt stopped after its two native guard commands,
before any of the fifteen study cases ran. Its CPU audit incorrectly compared
the raw speech-file length with the native generated-byte counter.

The native diagnostic writes the complete `live_tick` speech string, containing
the prompt followed by the completion. At source update 500, the saved output
was 105 bytes: the nine bytes of `The bird ` plus 96 generated bytes. The native
counter correctly reported 96. The checkpoint and output files were valid;
the checker interpreted their different byte counts as a failure.

`scripts/early_width_observations.py` now verifies fixed binary speech records
against the declared prompt, interval and completion length. It counts only
completion bytes against the native counter. The guard also compares every
speech byte with the production transcript, including its update markers,
without decoding or trimming potentially non-UTF8 generated data. The study's
argument builder rejects changes to the assumed speech policy.

The [speech verification](../reports/early-width-speech-audit.json) checks six
speech boundaries and fourteen rejected payload, transcript or policy changes.
Fixtures include repeated records, embedded prompt-like text, newlines, zero
bytes and non-UTF8 bytes. The existing orchestration/compiled-host preflight
also [passes unchanged controls](../reports/early-width-speech-preflight.json).

The corrected CPU audit was then applied to the preserved native guard:

- All sampled coordinates, statistics and source/update labels pass.
- Initial checkpoints are byte-identical between production and observer.
- Final checkpoints are byte-identical after 511 source updates, including
  replay and the scheduled speech event.
- The 105 speech bytes match the production transcript exactly.
- The CUDA diagnostic executable and all native model/observer source files
  are unchanged. The executable is copied by verified SHA-256 identity from
  the original pinned study build; no new binary is built for this repair.

The original failed run remains at `runs/prose-early-width`, with its protocol,
failure record, command logs and artifacts intact. The correction lives in a
separate checkout. A fresh declaration under `runs/prose-early-width-v2` uses
the same scientific specification and reruns the two native guards before
starting the fifteen cases. No completed case is selected, discarded or reused
from the failed attempt because none reached the study loop.

These checks establish the tiny native guard's compatibility. The subsequent
[completed study](prose-early-width-results.md) also reproduces both full-width
seed-1337 controls' original checkpoints and scores, then records every
width/rate outcome. No learning equation, model
default, training source, generation policy or reproduction admission changes.
