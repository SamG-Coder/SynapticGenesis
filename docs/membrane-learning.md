# Controlled membrane-objective learning comparison

This study asks whether an optional membrane objective improves language learning and retention in the existing 105M associative spiking model. The earlier [gradient audit](membrane-gradient-scale.md) showed that its correction strength grows substantially with learning history. Gradient reach or lower firing alone does not establish a useful learning rule.

The [specification](../data/membrane-learning-v1.json) is fixed before any of these founders learn. The current 411M curriculum study and the candidate's complete CUDA acceptance must finish first. The native model still owns forward computation, backward computation, replay, persistent recurrence and graph speech. The Python files only admit inputs, run sequential commands and inspect evidence.

## Cases and exposure

Every founder has 104,851,472 parameters, 1,024 channels, eight layers and 4,096 spiking neurons per layer: 32,768 spiking neurons in total. Each of seeds 1337, 2027 and 4099 receives all five settings, with its control first:

| Setting | Activity cost | Membrane cost | Membrane band |
| --- | ---: | ---: | ---: |
| Control | 0 | 0 | 1.5 |
| Activity comparison | 0.1 | 0 | 1.5 |
| Small membrane cost | 0 | 0.001 | 1.5 |
| Medium membrane cost | 0 | 0.01 | 1.5 |
| Large membrane cost | 0 | 0.1 | 1.5 |

These are exploratory coefficients spaced by factors of ten. They are not matched-gradient penalties, biological ages, or selected winners. The activity comparison tests the existing spike-activity objective against the direct membrane objective.

All 15 founders start from fresh randomized weights. Learning is one uninterrupted native `live` command through the original first two prose stages, ending at source observations 8,176 and 26,110. The complete original schedule is supplied without changing its identity; the command stops at the second endpoint. Source-target exposure is 1,045,096 bytes by the first endpoint and 3,339,920 by the second. The latter includes repeated curriculum passes and is not a unique corpus-size claim.

Learning uses the common learning rate 0.0003, chunk length 128, TF32 math, the 16,384-entry stage replay reservoir, one replay update per four source updates, and the original optimizer policy. The shared graph speaker produces 96 bytes every 500 source observations from `The bird `. Generated speech is not a target. Per model, the second endpoint has 26,110 source updates, 6,527 replay updates, 32,637 total optimizer updates and 4,992 generated bytes.

Initial weights, optimizer moments and recurrence must be identical across settings within a seed. The initial comparison normalizes only the checkpoint checksum, objective wrapper and activity-cost policy. Endpoint checks compare source counts, replay counts and exact reservoir payloads, source cursors, random-number state and speech policy. Checkpoint format and objective policy are also checked separately. The native loader remains the checksum authority; the bounded Python reader does not replace it.

## Measurements and controls

Both saved stage endpoints receive the existing four validation books, the two early-reader retention books, two newly introduced stage-two training monitors (books 572 and 420), and the original four generation prompts. That is 12 native assessment commands per endpoint, 30 endpoints and 360 assessment commands, in addition to 15 learning commands. Every book receives 65,536 byte targets in the fixed strict-FP32 assessment. Raw generation bytes, their decoded display and hashes are preserved.

The primary comparison is the equal-book validation mean at the second endpoint, paired against the same-seed control. Every setting and seed is retained. Each book is also reported individually, including the early-reader change from stage one and each stage-two training book before and after its introduction. The stage-two monitors are future training material at the first endpoint and training material at the second; they are not held-out validation. The question prompts are qualitative samples, not a QA accuracy benchmark. Reserved test books are not scored.

The seed-1337 control must exactly reproduce the archived initial, first-stage and second-stage checkpoints from the 16,384-entry replay study. Its original six book scores and four raw samples must match at both endpoints. Failure stops the study before another founder starts. This control also detects an unintended numerical change from the candidate executable, detailed logging or checkpoint-save frequency.

Source metrics are logged on every update, including short source tails. The reader checks the initial-session record, transition location, every update number and byte counters. Reports include byte-weighted language loss and firing, median/p95/maximum gradient norm, the count reported above the clipping threshold and the count equal to it. The native norm is the combined source-objective norm before clipping. It is printed to ten significant digits, so values equal to the threshold are ambiguous after rounding. Replay-update norms are not logged. The code does not report an exact replay or full-precision clipping count.

The saved native session includes live-loop throughput and latency. It includes replay, speech, detailed logging and periodic saves, while separate assessments and process setup sit outside that timing. It is not an isolated generation-speed benchmark. Comparison with older coarsely logged throughput needs that boundary stated explicitly.

## Serialization and evidence

The driver holds the Windows handle of the complete acceptance Python process, including its executable identity and creation time. It cannot advance when only a native child finishes or a PID is reused. A nonzero exit stops the study. After a successful exit, a fresh Python interpreter rechecks the acceptance protocol, all 20 command records and logs, the native and independent oracle results, compatibility results, and the entire completed 411M predecessor. This separate interpreter also keeps frozen candidate readers separate from the study's imported modules.

The candidate executable is pinned to SHA-256 `bbc94b245887c8a6d473ae8cbe44dda6afa5993e29504f32baabeb02971ec481`. Source material, code, archived controls and acceptance inputs are hashed at declaration and rechecked before learning. The [launch record](../reports/membrane-learning-launch.json) snapshots the waiting driver and revalidation of all 474 declared inputs; it is not a completed learning result. One model runs at a time. Its assessments finish before the next founder begins. Failure preserves the files and writes a failure record; restarting into the same study directory is refused.

The initial storage gate reserves at least 88,789,612,560 free bytes (about 82.7 GiB) for all initial/latest/stage checkpoints, transactional saves and a 10 GiB margin. It is rechecked before each founder. Existing studies and checkpoints are preserved.

## Host validation and use

[CPU audit evidence](../reports/membrane-learning-host-checks.json) covers the native-generated ordinary/wrapped host fixtures, the actual archived 105M states, the archived assessment comparator, full-source metric accounting, and 63 rejection paths. A separate successful mock handoff verifies that dispatch is reached only after both gates pass. The audit also invoked the real fresh-process verifier against the pending acceptance and confirmed refusal. Synthetic acceptance and process fixtures test orchestration only; they do not prove CUDA acceptance, language improvement or a completed fresh control.

From the main workspace, with the frozen study checkout in `runs/membrane-learning-worktree`:

```powershell
python -X utf8 runs/membrane-learning-worktree/tests/membrane_learning.py --out runs/membrane-learning-host-check
```

The audit requires the preserved local checkpoint/source fixtures named in its code. To additionally check a still-pending real acceptance, supply `--pending-acceptance` and its directory. That option is intentionally omitted once acceptance has completed.

Declare using the current complete acceptance-driver PID and its verified Python executable, then launch with the resulting protocol hash:

```powershell
python -X utf8 runs/membrane-learning-worktree/scripts/membrane_learning.py declare --out runs/membrane-learning-v1 --workspace D:/SynapticGenesis --acceptance D:/SynapticGenesis/runs/membrane-regularization-worktree/runs/membrane-acceptance-v1 --wait-pid <acceptance-driver-pid> --wait-executable <python-executable>
python -X utf8 runs/membrane-learning-worktree/scripts/membrane_learning.py run --out runs/membrane-learning-v1 --protocol-sha256 <declared-sha256>
```

Declaration is supported while the complete acceptance driver is available. The declaration and actual launch state are distinct evidence; a specification or successful host test does not mean learning ran. No setting is promoted to a parent, teacher or reproducing model by this experiment. Full-curriculum quality, 411M transfer, new-science retention and useful general answers remain separate measurements.
