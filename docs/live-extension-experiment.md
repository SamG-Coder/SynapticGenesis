# Admitting new lessons to a trained founder

The native [curriculum extension](live-curriculum.md#add-lessons-after-learning-has-started) now lets an existing model continue learning from additional selected content. This experiment uses the 1,186,304-parameter LIF founder from the [reading-to-science profile](retention.md#three-seed-result-and-usable-profile), already trained from random initialization through 12,000 online observations. It keeps that checkpoint intact and creates two continuations with the same starting weights, moments and live history.

The first admission appends the 96 single-object prerequisites from the existing [binding-v2 selection](../data/lessons-binding-v2.json) and trains for 4,000 more observations. Only after that session finishes does the second admission append the 1,728 two-object binding lessons and train for 24,000 observations. No new books, pretrained weights or teacher-generated answers enter either continuation. The script checks source identity, records SHA-256 manifests, and excludes exact documents from the reader and geography validation books. The reserved language test is not evaluated.

Both continuations retain a 1,024-window reservoir, use the same base rate of 0.0003 with a 0.25 stage multiplier, give the selected answer suffixes weight 64, and generate 96 bytes every 500 observations. They differ only in an explicit replay cadence override: one replay update after every four online observations, or after every observation. This changes replay examples/RNG use and the number of optimizer updates. It is an equal **online exposure** comparison, not an equal compute comparison.

## New lesson fit and old reading

The single-fact assay uses 144 context-reversal pairs formed from the 96 training lessons. Both members must be correct to pass a pair. The same lesson occurs with several alternative candidates; these are not 288 independent new examples. Candidate scoring compares two supplied answers. Greedy scoring requires the model to generate the exact answer itself. Both are training-fit measures: copying the single location suffices. The stronger binding assay uses 144 development groups with two facts, swapped assignments and both queried objects; always copying the first or last location cannot pass a group.

| Checkpoint | Replay cadence | Single-fact candidate pairs | Single-fact greedy pairs | Binding development groups | Earlier-reader loss |
| --- | --- | ---: | ---: | ---: | ---: |
| Before new lessons | Inherited every 4 | 5 / 144 | 0 / 144 | 0 / 144 | 2.21085 |
| After prerequisites | Every 4 | 144 / 144 | 144 / 144 | 0 / 144 | 2.45138 |
| After prerequisites | Every 1 | 112 / 144 | 60 / 144 | 0 / 144 | 2.25161 |
| After binding lessons | Every 4 | 144 / 144 | 138 / 144 | 0 / 144 | 2.55543 |
| After binding lessons | Every 1 | 139 / 144 | 129 / 144 | 0 / 144 | 2.51320 |

Reader loss is unweighted cross-entropy in nats per byte on the same independent book and fixed evaluation batches; lower is better. Every context-erased joint probe score remains zero. The ordinary-cadence model fits the simple lesson pairs completely after 4,000 observations, but some exact greedy answers are lost during the later stage. More replay protects earlier-reader performance most strongly during the first admission, while slowing acquisition of the new lesson answers. By the final checkpoint, both models have worse reader loss than their common starting point. Neither learns the two-object binding skill.

This is one founder and one seed. It does not show a general curriculum advantage, justify a default replay change, or establish useful open-ended conversation. The existing [optimization controls](binding-optimization.md) and [gated-trace experiment](gated-readout.md) also leave binding unresolved. Simply admitting more selected material and retaining a replay reservoir does not remove that limitation. [Full recorded measurements](../reports/live-extension-experiment.json).

## Continuity and performance

Both admissions preserve the existing replay windows, optimizer state, speech RNG and exposure history. Extension events occur at online updates 12,000 and 16,000, with all 1,024 reservoir entries retained at admission. The final checkpoints reach 40,000 online observations and 7,680 generated bytes. During the two added stages each model observes 1,980,048 source-byte targets and generates another 5,376 bytes. Generated text never supplies training targets.

| Added-stage work | Replay every 4 | Replay every 1 |
| --- | ---: | ---: |
| Online observations | 28,000 | 28,000 |
| Replay optimizer updates | 7,000 | 28,000 |
| Total optimizer updates | 35,000 | 56,000 |
| Live-loop time | 45.64 seconds | 66.90 seconds |
| Final-stage ordinary tick p95 | 6.33 ms | 7.21 ms |
| Final-stage tick including 96 generated bytes, p95 | 25.32 ms | 23.73 ms |

These RTX 5080 loop measurements include observation, replay, graph speech, logging and checkpoint writes, while excluding model/process setup and initial/final validation. Latency percentiles use the runtime's approximately 2.2%-wide histogram bins. The runs are sequential local measurements; small timing differences, particularly speech percentiles, are not evidence that more replay accelerates inference.

Separate seven-round, 1,024-byte decode checks measure graph medians of 157.68 and 149.15 microseconds per generated byte for the two checkpoints. Each agrees exactly with its own ordinary decode path on generated bytes, final state and logits. These include host sampling, transfers and synchronization; capture and prompt setup are excluded. The architecture is identical, so these values establish that inference remains usable after the additions rather than a replay-related decoding speedup.

## Reproduce and continue

Prepare the existing reading/science and binding-v2 sources, then create the seed-1337 founder with the documented [reading-to-science command](retention.md#three-seed-result-and-usable-profile). The experiment refuses to reuse an output directory:

```powershell
python scripts/live_extension_experiment.py --out runs/live-extension-demonstration
python scripts/live_extension_experiment.py --out runs/live-extension-more-replay --replay-every 1
python scripts/summarize_live_extension.py
```

The collector also reads the validation run paths listed in its source. Each experiment writes self-contained source editions and provenance under `data-prerequisites/` and `data-binding/`. The model's continuing checkpoint is `learner/latest.ckpt`; `stage-3.ckpt` and `stage-4.ckpt` archive the completed additions. Its next ordinary resume uses that run's `data-binding/curriculum.sg`. Since the final stage has reached its exposure limit, further learning requires another prepared extension. Population-owned models use the same admission operation and remain subject to simulation age and old-age death.

All eleven native suites passed. The new extension CLI covered 127 native invocations, including 32 before/at/after-boundary comparisons against a schedule declared at birth, repeated extension, optional SI, graph speech, answer weighting and population death. Maximum final-state discrepancy was 4.77e-7 and generated bytes were identical. The ordinary curriculum CLI also passed its 93 invocations and 24 ordinary plus eight weighted restart cases. Source preparation was checked with all three schedule versions through nine native invocations, with a 2.99e-8 maximum final-state discrepancy.
