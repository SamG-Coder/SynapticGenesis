# Bounded workspace for larger live models

The original live engine kept separate full-size gradient and decay arrays for
every window length it encountered. It also retained every distinct source
tail and replay shape. At 105 million parameters, each additional pair of
arrays alone cost about 800 MiB. Long book collections could therefore exceed
the GPU budget even when a short capacity run fitted comfortably.

`src/live_views.cuh` now owns the execution-view cache. Source tails and replay
windows each keep at most four recently used shapes. Eviction synchronizes
outstanding device work before releasing scratch. The permanent speaker and
its captured graph are never evicted. Tail views share the learner's recurrent
state; replay views still reset their own recurrent state.

Live views also share the root model's gradient and immutable decay-mask
allocations, alongside its existing weights and Adam moments. This is valid
for the existing sequential learn/replay/speak loop. Concurrent backward
updates through these views are not supported. Standalone batch learners,
frozen teachers, and independent scoring views keep their existing allocation
contracts. Checkpoint contents and neuron equations are unchanged.

| 104,851,472 | 6,422.2 MiB | 2,422.4 MiB | 7,056 | 1,348 |

This repeats the [same capacity workload](capacity-scaling.md), including all
source, replay and speech exposures. All reported per-round losses and all
scheduled speech bytes matched the previous executable exactly at every
size. The 105-million model's explicit arrays fell 62.3%. Timing differences
are small local observations with other desktop GPU contexts active; this
stage establishes a memory saving rather than a speed improvement.

The native suite passed 18/18 tests. A ragged stream exercised sixteen tail
lengths across all six cell types in FP32 and TF32: 48 native calls compared
the preserved old runtime, the new runtime, and split/resumed execution.
Complete checkpoints and old/new speech matched exactly. Three admitted
learned models also matched their old-runtime checkpoints and speech after
512 additional observations. A targeted CUDA memory-sanitizer run exercised
cache churn and reported zero errors.

The [capacity capture](../reports/bounded-live-capacity.json) and
[verification record](../reports/bounded-live-validation.json) retain the
measurements. Explicit arrays still exclude library/context overhead and
transient allocation during view construction. A larger context, teachers,
consolidation arrays or several resident population members need their own
resource budget. This change does not demonstrate improved language quality.
