# Larger live models

The current learned language prototype has 1,951,624 parameters and 2,048
spiking neurons (four blocks of 512). A capacity experiment successfully ran
the same associative cell at three larger sizes, all initialized randomly.
Training, replay and generation use the existing native C++/CUDA live loop.

| Channels | Neurons per block | Blocks | Total spiking neurons | Parameters | Learning bytes/s | Generated bytes/s | Explicit live arrays |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 256 | 512 | 4 | 2,048 | 1,951,624 | 34,649 | 6,322 | 150.6 MiB |
| 384 | 1,024 | 6 | 6,144 | 7,989,196 | 20,628 | 4,042 | 551.7 MiB |
| 512 | 2,048 | 8 | 16,384 | 27,260,432 | 12,317 | 2,734 | 1,780.1 MiB |
| 1,024 | 4,096 | 8 | 32,768 | 104,851,472 | 7,071 | 1,341 | 6,422.2 MiB |

These are local RTX 5080 measurements, with TF32 enabled and other desktop
GPU contexts active. The tokenizer is fixed UTF-8 bytes; these rates are not
directly comparable to subword tokens/s reported for other language models.
Neuron counts exclude channels, associative matrix entries and connections;
they are engineering state units rather than biological neuron equivalents.

Each shape used the same admitted four-reader training edition, seed and
source traversal. After 128 warm-up observations, three consecutive rounds
each measured 512 observations of up to 128 bytes. Ordinary reservoir replay
ran every four observations; the shared speaker generated 64 bytes every 128
observations. The table gives medians. Timings include learning, replay,
scheduled speech and synchronization, excluding initialization and checkpoint
saving. The separate generation timing uses the same speaker after learning,
three 1,024-byte runs after warm-up, and includes prompt processing and CPU
sampling. Fixed recurrent state and RNG reproduce identical bytes.

Explicit array counts subtract shared parameters, moments and recurrent
state. They exclude CUDA/cuBLAS overhead. Observed drops in free GPU memory
at round boundaries were 546, 994, 2,168 and 6,816 MiB respectively, relative
to an initialized CUDA context. These samples do not measure transient peaks.
The measured live engine cached different window lengths. Additional
document-tail lengths can therefore use substantially more memory than this
short workload. The subsequent [bounded workspace change](bounded-live-memory.md)
reduces that cost while preserving measured trajectories.

This test establishes that the larger models execute and learn finite
updates. It does not establish better language quality. Each saw only about
213,000 source target bytes, with small differences from document tails, and
no held-out quality comparison was performed. No benchmark founder was saved
or admitted as a parent. The [raw comparison](../reports/capacity-scaling.json)
contains all rounds and input hashes; [validation](../reports/capacity-validation.json)
records exact production-checkpoint controls in FP32 and TF32 plus a targeted
CUDA memory check.

## Scaling the data too

The earlier four-stage learning stream contained approximately 434,205
word-like units of actual book prose across twelve books. Another 911,616
word-like units came from 52,224 short template variants. Counting repeated
training exposures as new material would overstate that corpus's diversity.
The next data stage should reach millions of words of reviewed authored text,
then tens of millions as preparation and measured learning justify expansion.

More capacity and more data should be evaluated together. Transformer scaling
experiments found that optimal allocation depends on both model size and
training data, but studied much larger transformer models; their numerical
ratios are not validated prescriptions for this byte-level spiking design.
[Hoffmann et al.](https://arxiv.org/abs/2203.15556) Small-model research also
shows that restricted simple-language tasks can work below ten million
parameters; it does not establish broad general capability at that size.
[Eldan and Li](https://arxiv.org/abs/2305.07759)
